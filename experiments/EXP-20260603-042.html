    Rule 30 棱镜 — 一个像素种子如何长成彩色混沌瀑布 Rule 30 Prism — How a One-Pixel Seed Grows into a Colored Chaos Cascade

    🎮 好玩度🎮 FUN
    8/10
    ⚡ 科技感⚡ TECH
    8/10
    cellular-automatonrule-30chaoscomplexitypure-pythonzero-dependencypng-encodingdata-visualization
    // 假设HYPOTHESIS
    如果把一维元胞自动机 Rule 30 从单个中心像素开始逐行展开，并为不同列赋予不同色相，是否会在完全确定的规则下长出看似随机、却带有统计结构的彩色混沌图案？ If we unfold the one-dimensional cellular automaton Rule 30 row by row from a single center pixel and assign hues across columns, can a fully deterministic rule generate a pattern that looks random yet still carries measurable statistical structure?
    // 方法METHOD
    使用纯 Python 标准库在 401 列 × 280 行网格上模拟 Rule 30：每个新细胞由左、中、右三个邻居按 XOR 规则决定。初始状态只有中心 1 个活细胞。渲染时将活细胞按列位置映射为不同青蓝紫色调，并额外高亮中心列，再在底部绘制中心列随时间变化的二值条带。最后用手写 PNG 编码器输出零依赖图片，并统计总活细胞数、中心列 1/0 比例、跳变次数和最长连续段。 Using only the Python standard library, simulate Rule 30 on a 401-column × 280-row grid: each new cell is determined from its left, center, and right neighbors via the XOR-style Rule 30 update. The initial state contains a single active cell at the center. During rendering, active cells are color-mapped across cyan/blue/violet hues by column position, the center column is specially highlighted, and a binary stripe timeline of the center column is drawn at the bottom. A hand-rolled PNG encoder writes the final zero-dependency image, while total active cells, center-column 1/0 balance, transition count, and longest run are measured.
    // 结果RESULT
    成功 ✅ — 从 1 个种子像素出发，280 轮后长出了一个包含 36,378 个活细胞的彩色混沌三角形。最有趣的是中心列：280 个时刻中有 151 次为 1、129 次为 0，1 的占比约 53.93%，并发生了 133 次状态翻转，最长连续相同片段仅 7 步。也就是说，这个系统完全没有用随机数，却已经表现出很强的“伪随机”气质。Rule 30 再次提醒我们：复杂感并不一定来自复杂规则，很多时候，一个极简单的局部更新就足以制造混沌。 SUCCESS ✅ — Starting from a single seed pixel, 280 iterations grew a colored chaotic triangle containing 36,378 active cells. The most interesting object is the center column: across 280 time steps it is 1 for 151 rows and 0 for 129, giving a 53.93% one-balance, with 133 state transitions and a longest identical run of only 7 steps. In other words, the system uses no random number generator at all, yet already exhibits a strong pseudo-random personality. Rule 30 reminds us once again that complexity does not require complex rules — a tiny local update is often enough to manufacture chaos.
